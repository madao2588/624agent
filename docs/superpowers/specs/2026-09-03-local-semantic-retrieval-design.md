# 本地语义检索设计

## 目标

在不要求用户购买向量模型 API、也不把记忆文本发送给外部服务的前提下，为现有 BM25 检索增加真正的语义召回能力。该能力作为可选检索连接接入，不改变默认词法模式，也不破坏已有 OpenAI Compatible、DeepSeek 查询扩展等连接。

## 用户体验

- 检索方式增加“本地语义 · 免费”。
- 选择后不显示 API Key 和 Base URL 输入框。
- 模型固定为 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`，避免任意模型名或本地路径进入服务端。
- 首次连接时明确提示需要下载约 220 MB 的量化模型；下载完成后在本机推理。
- 连接成功后，记忆写入和回想均使用同一连接，已有 BM25、状态过滤、关系扩展仍然保留。
- 本地语义不可用时返回稳定且不包含记忆原文的错误信息。

## 技术方案

使用 FastEmbed 加载量化 ONNX 多语言模型，并通过现有 `Embedder` 协议接入 `HybridRetrievalPipeline`。最终候选仍由 BM25 与向量搜索分别召回，再用现有 RRF 融合，因此本次不重写检索主链路。

适配器采用惰性初始化：创建首个本地连接时第一次探测才加载模型；同一服务进程内的所有本地连接共享一个模型实例，推理调用串行进入该实例，避免多标签页重复占用数百 MB 内存或并发踩踏后端。FastEmbed 作为 `local` 可选依赖存在，基础服务仍可在不安装它时运行。

服务端把本地模型限定为单一白名单值：

```text
provider = local
base_url = local://fastembed
model = sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
api_key = absent
```

## 安全和失败边界

- `local` 请求携带 API Key、Base URL 或非白名单模型时拒绝。
- 外部向量供应商仍必须携带 API Key。
- 缺少 FastEmbed、模型下载失败、模型初始化失败和推理失败统一转换为安全的领域错误。
- 不把输入文本、密钥、底层异常详情回显到 API。
- 模型文件由 FastEmbed 的标准缓存管理，不在仓库中提交。

## 验收标准

1. 本地 provider 可在无 Key 情况下创建并返回 `embedding` 能力。
2. 本地 provider 的模型、地址和密钥约束有 API 测试覆盖。
3. 适配器的惰性加载、向量格式和安全错误有单元测试覆盖。
4. 演示页可直观选择本地语义模式，并正确发送无 Key 请求。
5. 现有外部连接、词法检索和全部测试不回归。
6. 使用真实本地模型完成中英文合成文本的语义检索冒烟测试。
7. LongMemEval 小样本结果与词法基线对照后，再决定是否进入会话分层召回。

## 本轮不做

- 不让用户输入任意 Hugging Face 模型或磁盘路径。
- 不在本轮引入向量数据库；继续使用现有 SQLite 向量存储。
- 不删除 BM25，也不把单一向量相似度当作最终排名。
- 不在无基准证据的情况下直接加入重排模型或复杂图检索。
