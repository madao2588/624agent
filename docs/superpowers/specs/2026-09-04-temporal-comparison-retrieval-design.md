# 双时态证据检索设计

## 要解决的问题

LongMemEval 的 knowledge-update 问题经常要求同时找出旧状态和新状态。例如：

> 以前多久和朋友打一次网球？现在多久一次？

当前混合检索能先找到相关会话，但会话里的泛泛讨论会挤占前几名，真正写明
“以前每周一次”和“现在每两周一次”的两条来源可能落到前十以外。这里缺少的
不是另一个全局搜索器，而是找到候选会话后，分别围绕两个时间视角找证据句。

## 方案比较

1. 总是按时间倒序：当前状态会改善，但历史问题会变差，也找不齐旧新两条证据。
2. 用 LLM 任意拆问题：覆盖面更广，但增加 API、延迟、隐私和不可复现风险。
3. 受约束的双时态检索：只在问题同时出现旧状态与当前状态标记时触发，在本地
   构造“过去”和“当前”两个检索视角，再进入候选会话找原文。

选择方案 3。它不生成答案，不猜测事实，也不把记忆正文发送给外部服务；只是
把明确的双时态问题拆成两个检索视角。

## 检索流程

1. 用原问题执行现有 BM25 与向量检索。
2. 只有同时检测到 prior 和 current 标记，并且存在成对问句或明确的旧新比较
   结构时，才提取共享主题词。
3. 构造 `previous historical state + topic` 与
   `current latest state + topic` 两个本地向量查询。
4. 用已有词法命中建立本地 topic bridge，补回同主题的其他会话。
5. 在最多 10 个候选会话内分别搜索两个查询。双时态路径把会话内候选窗口扩大到
   16 条后再过滤，避免先截断后过滤而丢掉真正证据。
6. 每个时间视角选一条高相关、互不重复的证据，放到最终结果前部；其余结果保持
   原有融合顺序。
7. 继续应用忘记请求和提示词注入过滤。

## 触发边界

- 支持英语和中文的明确旧/新对比标记。
- “之前的对话”仍只是来源指代，不能单独触发历史状态排序。
- 只有 current 或只有 previous 的单时态问题不触发双证据保留。
- “以前的公司”“今天之前”等描述性修饰不构成旧新比较，不触发该路径。
- 对“多久一次”问题，证据必须包含明确周期表达；其他答案类型暂不套用频率规则。
- `top_k=1` 不运行第二阶段，避免为了补证据破坏单条精确命中。
- 本阶段优化证据召回，不负责计算频率差、时间差或生成最终自然语言答案。

## 验收标准

- 合成测试中，两条旧/新证据进入前五，且不会返回其他用户的数据。
- LongMemEval `f685340e` 的两个金标由原先前十未找齐提升为前五找齐。
- 已冻结的六类样本不发生 Recall 或 nDCG 回退。
- 本地质量检查、完整测试和 GitHub 容器预检通过。
