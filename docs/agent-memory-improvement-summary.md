# 624agent 完善方向总结

更新日期：2026-09-02

## 一句话结论

624agent 已经不是一个只能靠特殊符号搜索的原型。它现在具备符合评测接口的持久化记忆、BM25 检索、中英查询扩展、显式状态更新、有限关系桥接、偏好与流程标签，以及可选的向量接口。下一阶段不需要推倒重来，重点是补齐时间、关系、记忆治理、个性化和规则理解，并把当前本地版本整理成可复现的正式提交。

正式参评版本应优先保持确定、可复现和低成本。DeepSeek 适合作为演示和可选查询增强；向量模型继续保留接口，但在没有合适额度时不作为主线依赖。

## 当前系统是什么

默认检索链路：

```text
Add
  → 校验请求
  → 保存原始消息
  → 建立中文分词与 FTS5 索引
  → 识别显式更新、偏好和流程标签
  → 提交 SQLite 事务

Search
  → 分析问题和选项
  → BM25 / FTS5 召回
  → 状态链、标签、实体桥和会话上下文补全
  → 排序并返回原始记忆证据
```

启用 DeepSeek 时：

```text
问题
  → DeepSeek 生成中英双语检索词
  → 本地检索原始记忆
  → 返回证据
```

DeepSeek 目前不是向量模型，也不接收记忆正文。真正的向量通路已经预留：写入时生成记忆向量，搜索时生成问题向量，再融合 BM25 与余弦相似度结果；没有外部 Embedding 服务时可以完全不启用。

## 已完成的底座

- 符合官方同步 Add / Search 契约。
- 原始消息持久化，重启后仍可搜索。
- `request_id` 幂等与冲突检测。
- 严格按照 `user_id` 隔离存储和检索。
- SQLite FTS5 与 BM25 排序。
- 中文连续文本的 CJK 双字索引。
- 查询选项参与检索。
- 同会话上下文补全。
- 显式计划修改与 `supersedes` 状态链。
- 偏好和流程记忆的辅助标签。
- 有边界的跨会话实体关系桥接。
- DeepSeek 双语查询扩展与噪声控制。
- OpenAI 兼容 Embedding 接口、向量持久化和混合排序骨架。
- Health、鉴权、并发预检、Docker、CI 和演示页面。
- 当前本地验证快照：118 项测试通过，离线记忆挑战、Ruff、Mypy、编译和服务冒烟检查通过。

## 必须先处理的提交问题

### 1. 固定正式评测模式

正式提交不能依赖演示页面里的临时设置。需要增加一个固定的 evaluation 配置，明确：

- 使用哪些检索模块；
- 是否允许外部模型；
- 模型名称、提示词和超时；
- 失败时返回什么状态；
- 如何保证主办方复现同样结果。

当前官网 Full 清单写有 Add/Search 使用 `gpt-4o-mini` 的要求。纯规则系统是否豁免、代码提交路径由谁提供模型凭证，都需要在冻结参评版本前向主办方确认。未确认前，不应把 DeepSeek 当成正式评测依赖。

### 2. 整理 Git 和版本

当前 GitHub `main` 仍是旧版本，本地积累了整套未提交改动。提交前需要：

1. 审查全部变更和新增文件；
2. 修正文档与实际行为不一致的地方；
3. 运行完整测试和 Docker 预检；
4. 创建结构清晰的提交；
5. 推送 GitHub；
6. 固定 commit SHA 和版本标签。

### 3. 修正文档

README 仍描述 Key 只保存在服务端和 `sessionStorage`，但演示页面已经支持用户选择将配置保存在浏览器本地。提交说明仍写着 Add/Search 不调用 LLM，也没有包含最近增加的状态链、标签、DeepSeek 和向量接口。这些内容必须与最终参评配置保持一致。

### 4. 做正式容量验收

官方正式检索最多读取 `top_k=100`。评测界面允许较高 Add/Search 并发，因此需要验证：

- Add 64 并发；
- Search 256 并发；
- Top K 100；
- SQLite 锁冲突和有限重试；
- 服务重启与数据恢复；
- Docker 冷启动；
- 零跨用户结果；
- 无正文和密钥泄漏到日志。

## 对评测最有价值的能力完善

### 1. 结构化事件记忆

在保留原始消息的同时，为检索建立辅助结构：人物、时间、地点、动作、对象、事件状态和来源消息。结构化结果只负责找证据，Search 仍然返回原始内容。

### 2. 指代和别名

识别“林老师 / 他 / 那位老师”“西湖边 / 那里 / 原地点”等表达指向同一实体。别名和指代必须带来源和置信度，不能把推测当作事实。

### 3. 完整的时间与事件状态

补齐：

- 绝对时间和相对时间；
- 事件先后顺序；
- 延期、提前、取消、恢复；
- 当前状态与历史状态；
- 基于消息时间解释“昨天、下周、两天后”；
- 隐式更新和矛盾，而不只依赖“改到、改为”等明显词语。

### 4. 记忆治理

为记忆建立生效、被替代、已取消、已遗忘和历史保留状态。普通问题优先返回有效状态；只有询问历史时才主动展开旧状态。

### 5. 多跳关系图

把人物、事件、地点和对象组织成带原始证据的关系图，支持两到三跳检索。例如：

```text
我 → 同事 Omar → 推荐 Juniper Cafe → 位于河边
```

路径中的每一步都必须能回到原始消息，不能生成新的事实。

### 6. 个性化与偏好

区分喜欢、讨厌、习惯、一次行为和长期偏好；结合频率、强度、新旧冲突和来源时间。画像只能用于检索，不能替代原始证据。

### 7. 规则和流程

从规则记忆中索引条件、必须动作、禁止事项、执行顺序、例外和规则更新，保证检索时能取回一组完整规则，而不是只命中一句含有“必须”的文本。

### 8. 多路召回与重排

在不强制使用付费向量的前提下，组合：

- BM25 原文召回；
- 人物、地点和事件召回；
- 时间与状态召回；
- 偏好与流程通道；
- 多跳关系召回；
- 可选且合规的 LLM 查询扩展；
- 去重、证据多样性和相关性重排。

### 9. 动态上下文补全

根据问题补齐同一事件、更新链和关系路径，不再机械地固定取命中消息前后一条，减少无关邻居进入 Top K。

### 10. 证据不足判断

增加可靠的相关性阈值。没有足够证据时返回空数组，不为凑满 Top K 返回噪声，也不生成最终答案。

## 测试和评估体系

建立合法的合成测试集，覆盖公开能力维度，但不使用私有题目、金标或泄漏数据。

重点场景：

- 中英混合和跨语言表达；
- 代词、简称和同名人物；
- 两跳、三跳关系；
- 隐式计划变化；
- 取消后恢复；
- 偏好反转；
- 条件规则、禁止事项和例外；
- 大量干扰会话；
- 长上下文；
- 无证据拒答；
- 跨用户攻击；
- Prompt Injection 记忆；
- 重复、乱序和并发 Add；
- 数据库重启和迁移。

内部指标：

- Recall@K；
- MRR；
- nDCG；
- 噪声率；
- 空结果准确性；
- Add/Search 延迟；
- 各能力模块的消融对比。

内部指标只用于开发诊断，不冒充官方榜单分数。

## 工程和运行保障

- SQLite schema 迁移和版本管理；
- 大批量写入和索引优化；
- 外部服务超时、有限重试、熔断和费用上限；
- 结构化延迟与错误日志，不记录正文和密钥；
- 数据备份、恢复和评测结束后的清理；
- 鉴权、限流和密钥轮换说明；
- 固定依赖版本和可复现 Docker 构建；
- CI 最大并发预检、秘密扫描和容器回归；
- 健康检查同时覆盖数据库可用性和必要索引状态。

## 演示页面最后完善

- 记忆时间线；
- 当前状态与历史状态分栏；
- 人物关系图；
- 每条证据的匹配原因；
- 本地、DeepSeek 和 Embedding 模式的清晰说明；
- Key 保存风险提示和一键清除；
- 多种测试场景入口；
- 检索过程可视化，但不展示伪造分数。

## 明确不做

- 不自己训练向量模型；
- 不生成评测题的最终答案；
- 不硬编码基准题目或答案；
- 不跨 `user_id` 共享记忆；
- 不用摘要替换原始证据；
- 文本赛道稳定前不扩展多模态和代码记忆赛道。

## 推荐实施顺序

1. **提交与合规整理**：固定 evaluation 模式、修正文档、整理 Git。
2. **事件与实体层**：人物、地点、时间、动作、别名和指代。
3. **状态与治理层**：更新、取消、恢复、遗忘和历史查询。
4. **关系与个性化层**：多跳关系、偏好、规则和流程。
5. **排序层**：多路召回、动态上下文、去重、阈值和重排。
6. **评测层**：能力测试集、内部指标、最大并发和故障测试。
7. **交付层**：Docker 复现、CI、提交说明、固定 commit 和版本标签。
8. **演示层**：时间线、关系图和可解释检索界面。

每一阶段先补回归测试，再修改实现，最后做黑盒 API 验收。正式评测模式与演示模式分开，避免为了界面方便破坏可复现性。

## 完成标准

当下面条件全部满足时，才算真正准备好提交：

- 当前改动已审查、提交并推送；
- README、提交说明和实际运行方式一致；
- 主办方的模型规则已确认；
- Add/Search 契约、Top K、并发和鉴权通过黑盒预检；
- 所有能力测试和静态检查通过；
- Docker 从干净仓库可以独立构建和启动；
- 搜索只返回当前用户的原始记忆证据；
- 没有密钥、正文或私有评测材料泄漏；
- 固定 commit SHA、版本标签和复现说明已经准备完成。
